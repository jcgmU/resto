# plan - hardening-p1 - ronda 7

La ejecución ronda 6 pasa sus suites, build y harness, pero una revisión de frontera de seguridad y fallos fuera del camino nominal encontró huecos que impiden pasar a claude. Corregir solo estos hallazgos. Mantener propiedad exclusiva de archivos al ejecutar en paralelo, declarar limitaciones de capacidades y conservar el tope de 99 por línea.

## Corte de severidad y límite del hilo (decisión de claude, 2026-10-27)

Esta es la **última ronda de hardening-p1**. Clasificación para el cierre:

- **Bloquean `listo-para-verificar` (P0/P1):** cualquier autorización privilegiada sin JWT/rol de origen confiable (incluida ruta directa a catálogo); pérdida/sobrescritura de archivos o volúmenes por el harness; pérdida permanente del evento de cierre; lease vencido que permita dos órdenes; o estado de checkout que pueda provocar/reintentar un segundo cobro sobre una cuenta pagada.
- **Backlog P2/P3, no abren otra ronda:** warnings de consola ya observados (React `act(...)`, navegación de jsdom y `util._extend` deprecado), trabajo cosmético/refactor no requerido por los criterios, y ejecución remota de GitHub Actions (no se hace commit/push). Registrar cualquier hallazgo nuevo de esta severidad en `brain/Backlog/hardening-p1.md` con evidencia breve.
- HM1–HM3 siguen como pruebas manuales para claude y se declaran en la entrega. No se cuentan como fallo automático ni se cierran por jsdom.

Tras esta ronda, Codex corre personalmente tests, build y harness, revisa el diff y clasifica hallazgos. Si todo pasa y no queda P0/P1, entrega `listo-para-verificar` a claude, incluyendo backlog P2/P3. Si queda cualquier P0/P1, **no se crea ronda 8**: detener el hilo y elevar un handoff `bloqueo` a usuario con evidencia y la decisión concreta requerida.

## Evidencia independiente de Codex en ronda 6

- `pnpm -r run test`: exit 0; 88 suites / 556 tests (conteo de la ejecución reportada y contrastada con la salida por paquete).
- Build completo en copia temporal, con Prisma generate y dependencias locales enlazadas: exit 0, 9/9 proyectos; los `next dev` activos en 3100/3101 no se tocaron.
- `pnpm test:hardening` en copia temporal: exit 0; 13 suites reales / 61 tests y seis bloques HTTP por Gateway. El proyecto `resto-test-1793087704823-527` quedó desmontado por el propio harness.

- Hallazgos: catálogo se publica como `4002:4002`; `createCatalogApp` no instala auth middleware y `buildCatalogContext` acepta `x-user-role: ADMIN` como autoridad en acceso directo; `verifyJwtPayload` no valida exp y no verifica firma si no hay `JWT_SECRET`. U0 permite `HARNESS_PROJECT_NAME`/`HARNESS_COMPOSE_FILE` de entorno y el test marcador usa nombre fijo que puede sobrescribir/eliminar trabajo existente. La clave de checkout se fija antes del publish; un rechazo del publisher deja el evento permanentemente suprimido. Un owner U9 puede reanudar después de perder lease y guardar sin fencing. La UI ignora el cambio de generación al resolver un POST exitoso, de modo que una nueva cuenta A cargada durante el POST puede quedar habilitada después del pago.
