## Hallazgos comprobados por Codex en ronda 5

- `pnpm -r run test`: exit 0, 87 suites y 550 tests.
- Build completo ejecutado en copia temporal con `.next` de `next dev` preservado: exit 0 (9 proyectos). La primera tentativa falló por copia sin dependencias locales y generación de Prisma omitida; tras enlazar dependencias por workspace y generar clientes, el build final pasó.
- `pnpm test:hardening` en copia aislada: exit 0, 13 suites reales / 49 tests y seis bloques E2E HTTP Gateway; el harness eliminó su proyecto Compose `resto-test-1793083545834-474` al finalizar. `docker ps -a --filter name=resto-test` quedó vacío.
- `git diff --check`: exit 0.
- Reproducción del bypass de catálogo reportada en la revisión anterior y repetida en este turno: contexto `x-role: ADMIN` sin rol verificado produjo HTTP 200 y creó categoría. La prueba de ronda 6 debe atravesar el gateway autenticado con guest y spoof header.
- Código confirma que `ConfirmCheckout` omite evento si ya existe Payment; el test de retry no cuenta publicaciones. `CartUseCases.addCartItem` valida sesión antes de mutar Redis y no coordina esa mutación con checkout. `OrderUseCases` decide si reserva sigue en curso usando `isOperationInFlight` en memoria, sin ownership distribuido.
- `HttpSessionServiceAdapter.getSession` devuelve una sesión activa sintética para `s-smoke-e2e`.
- Checkout compara el id seleccionado pero no una generación única; A→B→A puede aceptar una respuesta de la primera A. El bloque visual del error sigue condicionado a `bill` existente.
- Las suites reales aún cargan `.env` y usan valores por defecto de Postgres/Redis; fuera del harness pueden apuntar a servicios locales. `waitForHttp` considera saludable cualquier estado <500. Si `compose up --wait` falla tras crear parte del proyecto, `infraStarted` todavía es falso y cleanup no lo desmonta.

La revisión no acredita HM1–HM3 en navegador real. Codex entrega este plan correctivo al ejecutor y se detiene hasta recibir su nueva ejecución.
